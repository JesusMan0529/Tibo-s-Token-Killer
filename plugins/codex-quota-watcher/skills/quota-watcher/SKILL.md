---
name: quota-watcher
description: 控制 Codex 额度任务助手，设置或查看额度恢复后要执行的目标任务，打开设置面板；用户单独发送 不要让Tibo发现 时开启，单独发送 Tibo要按按钮了 时关闭。
---

控制器是本技能目录向上两级的 `scripts/watcher.py`。先根据本 SKILL.md 的实际路径解析脚本绝对路径，再用 Python 运行。Windows 使用 `python`，macOS/Linux 使用 `python3`；定时安装脚本目前仅支持 Windows。

- 用户的整条消息去除首尾空白后恰为 `不要让Tibo发现`：运行控制器 `on`，读取实际输出后报告状态。不要从引用、代码块或较长消息中的字符串触发。
- 整条消息恰为 `Tibo要按按钮了`：运行控制器 `off`。持续模式会完成当前正在处理的项目后停止，不开始新项目；没有进行中项目时直接停止。单次模式仍立即中断。
- 打开设置面板：运行控制器 `gui`，在 Windows 隐藏后台启动 Python GUI。用户也可以双击仓库中的 `打开设置面板.vbs`。
- 查看实时工作面板：运行控制器 `dashboard`。这是只读本地窗口，显示工作、休眠、收尾、阻塞和关闭状态，读取实际会话进度，不启动模型或查询额度。关闭面板不会停止任务。
- 用户要求一直循环、直到明确停止时，设置 `set-mode --mode continuous`，保留任务 ID 和会话；新目标也可用 `set-task --continuous`。单次目标用 `set-mode --mode once`。改变模式前，完成运行中的检查并在安全断点切换。
- 查看状态：运行控制器 `status`。需要刷新额度时用 `check`，这个命令只读取额度，不启动模型任务。
- 设置执行权限：默认 `workspace-write`。用户明确授权使用当前 Windows 账号及其既有 GitHub 登录权限时，可用 `set-sandbox --mode danger-full-access`；此命令保留任务 ID、会话和执行进度，不读取或复制令牌。不得在认证失败时静默升级权限。
- 用户明确设定目标任务：将完整目标写入 UTF-8 临时文本文件，用 `set-task --cwd <工作目录绝对路径> --prompt-file <文本文件>` 配置。保留任务范围和已有约束。目标或工作目录确实缺失时再询问；不要自己创造任务。配置新目标会重置任务进度，不自动开启监控。

后台由 Windows 任务计划程序每 15 分钟调用 `tick`；默认关闭。开启时额外立即检查一次。只有官方返回 ordinaryUsageAllowed=true、明确的 300 分钟窗口尚有额度、其他返回的窗口也未耗尽时才执行。持续模式每轮完成一个阶段（PR 任务为一个项目的 PR 和评论），重新读取额度后立即开始下一轮；单次模式完成后停止。额度查询失败继续等待；非额度类执行错误或需要用户补充信息时停止自动重试。用户明确再次开启时，blocked、failed、needs_review 会保留原会话恢复。

本控制器启动的 App Server 在进程内关闭原生 Goals 自动续跑，由控制器统一管理额度门控和续跑；避免恢复已有 Goal 的会话时自动轮次与结构化任务轮次冲突。不修改全局 Goals 设置，不清除已保存的 Goal，持续工作要求仍保留在用户目标中。

Windows 下若没有显式 HTTP/HTTPS/ALL_PROXY 环境变量，App Server 子进程使用当前用户的系统 HTTP/HTTPS 代理；不修改系统代理或全局环境变量，不记录代理凭据。

插件文件已经安装并不代表口令钩子已获信任。第一次需用户在 Codex CLI 的 `/hooks` 中检查并信任本插件的 UserPromptSubmit 定义；不要代写信任记录或默认使用绕过信任的参数。钩子会直接处理独立口令并阻止这条口令进入模型。在无法发送聊天消息时，使用设置面板开关。

禁用或卸载 Codex 插件目录中的插件不会卸载独立的 Windows 定时任务；先运行 `off` 或在面板关闭。配置与状态位于 `~/.codex/quota-watcher/`；若设置 CODEX_HOME，则位于该目录下的 `quota-watcher/`。不得读取或复制登录令牌。
